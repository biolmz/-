# 感官评价线上评分系统

面向「啤酒麦糟酥性饼干感官评价方案」的线上评分系统。评价员用手机/平板扫码或点链接即可评分，组织者在后台实时查看进度、统计结果并导出数据。

**零第三方依赖** —— 只用 Node.js 内置模块，把整个文件夹拷到服务器上 `node server.js` 就能跑，不需要 `npm install`，不需要数据库。

---

## 一、功能一览

### 评价员端（`/`）
- 凭评价员编号进入，同一编号再次进入自动续评（进度不丢）
- 首次进入需在线阅读并签署**知情同意书**（内容与方案一致：评价目的、成分与致敏原、糖醇耐受、权利与退出、数据隐私、保密义务、联系人）
- 按方案要求对每位评价员**随机打乱样品评价顺序**（三位数盲编码）
- 5 项指标按标准三档选档 → 档内滑杆微调，**分数被限制在该档区间内**，避免超出标准
- 总分实时计算，支持上下一个样品切换、断点续评
- 可选备注（异常情况说明）
- 全部样品完成后确认提交，提交后锁定

### 管理端（`/admin`）
- 密码登录（默认 `admin123`，可修改）
- **场次管理**：一键「关闭本次评分」/「重新开放」；一键「新建下次评分」（当前场次自动归档、样品编码可选继承），历史场次随时切换查看
- **概览**：样品数 / 评价员数 / 已提交 / 进行中 / 未开始 / 完成率、样品总分排名
- **异常值提示**：按方案 6(4)，自动标出个体总分偏离全体均值 ±2 倍标准差的记录，供人工复核
- **统计分析**：各样品各项指标 **均值 ± 标准差**、总分均值 ± 标准差、排名
- **数据分析 · ANOVA**：一键完成 **单因素方差分析（One-way ANOVA）+ Duncan 新复极差多重比较**，并自动绘制 **柱状图（含误差线与显著性字母）、雷达图、各指标得分率分组柱状图**；图表可导出 PNG / SVG，分析表可导出 CSV（详见第六节）
- **原始记录**：逐条评分明细，可按评价员编号 / 姓名 / 样品编号筛选
- **样品与评价员**：样品编码增删改、一键随机生成三位数编号、评价员进度与删除
- **系统设置**：提示语编辑、修改管理密码、评分标准 JSON 在线编辑（含恢复默认）、清空本场数据
- **导出 CSV**：本场原始记录、本场统计汇总、本场统计分析、全部场次原始记录；UTF-8 带 BOM，Excel / WPS 双击直接打开不乱码

### 场次机制
| 操作 | 效果 |
|---|---|
| 关闭本次评分 | 新评价员无法进入；已进入但未提交的仍可继续完成并提交（避免数据丢失）；统计与导出不受影响 |
| 重新开放 | 恢复进入与评分 |
| 新建下次评分 | 当前场次自动关闭并归档 → 新场次成为当前场次；可选是否继承本次的样品编码；评价员与评分从零开始 |
| 查看历史场次 | 在下拉框切换，历史场次为只读，可随时导出 |
| 设为当前场次 | 误关后可把某场次重新设为评价员看到的那一场 |
| 删除场次 | 永久删除该场次数据（至少保留一个场次） |

## 二、目录结构

```
评价网站/
├── server.js                 # 后端服务（HTTP 服务 + REST API + 数据读写）
├── package.json              # 无任何依赖
├── lib/
│   └── stats.js              # 零依赖统计学库（ANOVA / Duncan / F 分布等）
├── tools/
│   └── seed-demo.js          # 演示数据生成 / 清理（用于预览分析功能）
├── deploy/
│   └── sensory-eval.service  # systemd 服务单元（部署方式 C）
├── start.sh / start.bat      # 一键启动脚本
├── ecosystem.config.js       # PM2 配置（可选）
├── public/                   # 前端静态资源
│   ├── index.html            # 评价员端
│   ├── admin.html            # 管理端
│   ├── css/style.css
│   └── js/app.js, admin.js, charts.js   # charts.js 为纯 SVG 绘图（无需联网）
└── data/                     # 运行时自动生成，所有数据都在这里
    ├── config.json           # 站点配置、评分标准、知情同意书、管理密码、当前场次
    ├── sessions.json         # 全部评价场次（含各自的样品与评分记录）
    └── secret.key            # 登录令牌签名密钥
```

> **备份只需拷贝 `data/` 目录**。

## 三、本地运行

```bash
cd 评价网站
node server.js
```

启动后终端会打印访问地址，例如：

```
  本机访问   http://localhost:8200
  局域网访问 http://192.168.1.20:8200   ← 评价员用手机/平板打开
  管理后台   http://localhost:8200/admin
  管理密码   默认 admin123（请登录后台后立即修改）
```

同一局域网内，评价员手机连同一个 WiFi 直接访问局域网地址即可。
Windows 双击 `start.bat`、macOS/Linux 执行 `./start.sh` 效果相同。

## 四、部署到服务器

### 方式 A：直接运行（最简单）

```bash
# 1. 把整个「评价网站」文件夹上传到服务器，例如 /opt/sensory-eval
# 2. 服务器装好 Node.js 18+（推荐 20 LTS）
node -v

# 3. 启动
cd /opt/sensory-eval
PORT=8200 ADMIN_PASSWORD='你的强密码' node server.js
```

想让它退出 SSH 后继续运行：

```bash
nohup node server.js > app.log 2>&1 &
```

### 方式 B：PM2（推荐，带开机自启和崩溃重启）

```bash
npm install -g pm2
cd /opt/sensory-eval
pm2 start ecosystem.config.js
pm2 save
pm2 startup          # 按提示执行输出的那条命令，配置开机自启
```

常用命令：`pm2 status` / `pm2 logs sensory-eval` / `pm2 restart sensory-eval`

### 方式 C：systemd

把 `deploy/sensory-eval.service` 复制到 `/etc/systemd/system/`，按需修改路径后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now sensory-eval
sudo systemctl status sensory-eval
```

### 用 Nginx 做反向代理 + 域名 + HTTPS（可选）

```nginx
server {
    listen 80;
    server_name eval.example.com;

    client_max_body_size 2m;

    location / {
        proxy_pass         http://127.0.0.1:8200;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
```

配置好后用 `certbot --nginx` 一键签发 HTTPS 证书。评价员端和管理端共用同一个端口，无需额外配置。

## 六、使用流程

1. **部署后准备**：进入管理端 → 「样品与评价员」→ 设置样品编码（或点「随机生成编号」按方案生成三位数编码）→ 保存。
2. **确认开放**：场次栏显示「开放中」即可；若是「已关闭」，点「重新开放本次评分」。
3. **发放入口**：把 `http://你的域名/` 发给评价员，或用草料等工具生成二维码贴在现场。
4. **现场评价**：评价员输入编号 → 签署知情同意书 → 逐个样品评分 → 提交。
5. **查看进度**：管理端「概览」「原始记录」实时刷新（点右上角「刷新」）。
6. **导出数据**：点「导出本场原始数据」得到 `感官评价原始记录-<场次名>.csv`，点「导出本场统计汇总」得到均值±标准差汇总表。
7. **结束本次评分**：点「关闭本次评分」，评价员端停止接收新的进入。
8. **开始下一次**：点「＋ 新建下次评分」→ 填场次名 → 勾选是否继承样品编码 → 创建。历史场次数据完整保留，可在下拉框切换查看或导出。

### 导出的 CSV 里有什么

**原始记录**（`感官评价原始记录-<场次名>.csv`）列顺序：场次、评价员编号、姓名、样品编号、样品备注、各指标得分、总分、评价员备注、提交状态、提交时间、记录更新时间。

**统计汇总**（`感官评价统计汇总-<场次名>.csv`）列顺序：场次、样品编号、备注、有效样本数、各指标均值、各指标标准差、总分均值、总分标准差、排名。

两份都是 UTF-8 带 BOM，Excel / WPS 双击直接打开不乱码；导入 SPSS 时选 UTF-8 编码，数值列可直接做单因素方差分析 + Duncan 多重比较。

> 需要跨场次汇总时，用「系统设置 → 导出全部场次原始数据」，得到的 CSV 带「场次」列，可直接在 SPSS 里按该列分组。

## 七、数据分析（单因素方差分析 · Duncan 多重比较 · 图表）

管理端顶部的 **「数据分析 · ANOVA」** 标签页，会对当前场次**已提交**的评价数据自动完成统计检验与绘图，无需借助 SPSS / Excel，**断网、纯内网环境也能用**（图表为纯 SVG 本地绘制，统计量为内置零依赖算法，均不依赖任何 CDN 或第三方库）。

### 分析内容

对 **总分** 及 **5 项指标（形态 / 色泽 / 滋味与口感 / 组织 / 整体接受度）** 分别给出：

| 板块 | 内容 |
|---|---|
| 描述统计 | 各样品的 n、均值、标准差、标准误、变异系数 CV、最小值、最大值、中位数、极差 |
| 方差分析表 | 平方和 SS（组间/组内/总）、自由度 df、均方 MS、F 值、P 值、显著性判断 |
| Duncan 多重比较 | 样品两两比较的均值差、临界值 R、是否显著，以及**显著性字母分组**（同一字母表示差异不显著，字母不同表示差异显著） |

- 显著性水平 **α 可切换**：下拉框选择 `0.05` / `0.01` / `0.10` 后自动重新计算。
- 多重比较采用 **Duncan 新复极差法（DMRT）**：临界值 `R = r_p · √(MS_w/2 · (1/nᵢ + 1/nⱼ))`，其中 `r_p = q_{1-α_p}(p, ν)`，`α_p = 1-(1-α)^(p-1)`；`q` 值由**学生化极差分布**数值积分求得，与统计表一致。
- 显著性字母按**最大连续不显著区间**归组，自动消去被包含组后依次标注 a、b、c…。

### 图表（可导出 PNG / SVG）

1. **样品总分对比**（柱状图）：柱高为均值，误差线为标准差，柱顶字母为 Duncan 显著性分组。
2. **感官品质雷达图**：各样品的 5 项指标按满分归一化后叠加对比，直观看风味轮廓。
3. **各项指标得分率对比**（分组柱状图）：各样品在每项指标上的得分占该项满分的百分比，便于跨指标比较。

每张图右上角都有 **PNG / SVG** 按钮：PNG 为 2 倍分辨率位图（直接贴进报告 / PPT），SVG 为矢量图（可无损缩放、可再编辑）。

### 导出

- 点「导出统计分析」得到 `感官评价统计分析-<场次名>.csv`，含 **描述统计 / 方差分析表 / Duncan 多重比较** 三段内容。
- 图表可逐张导出 PNG / SVG；原始数据与汇总表仍在「概览」「原始记录」页导出。

> **统计前提**：单因素方差分析假设各组近似正态、方差齐性。感官评分（尤其是 9 分制以上的合成分）通常满足；若某组数据明显偏态或方差不齐，建议结合描述统计中的 CV 与极差人工复核，或用 SPSS 做非参数检验（Kruskal-Wallis）。

## 八、常见问题

**Q：评价员中途换了设备，进度会丢吗？**
不会。进度按评价员编号保存在服务器上，换设备重新输入同一编号即可继续。

**Q：评价员提交后发现打错了怎么办？**
管理端目前不提供在线改分（避免数据被篡改）。可让评价员重新用**另一个编号**评一次，或在「原始记录」中定位到该条记录后，直接修改服务器 `data/evaluators.json` 中对应数值（改前请先备份该文件）。

**Q：数据量能撑多大？**
JSON 文件存储，单场评价（20 名评价员 × 20 个样品 = 400 条记录）毫无压力，几十个场次累计也完全够用。若后续要做成常态化平台、上千条记录并发写入，建议改为 SQLite/MySQL，接口层已经解耦，替换 `data/` 读写部分即可。

**Q：想再做一次评价，要重新部署吗？**
不需要。管理端点「＋ 新建下次评分」即可，历史场次自动归档、数据保留、随时可导出。

**Q：误点了「关闭本次评分」怎么办？**
点同一位置的「重新开放本次评分」即可；关闭期间评价员端只是不能进入，已有数据不受影响。

**Q：备份怎么做？**
停服后直接拷贝 `data/` 目录；或不停服直接拷贝（写入采用临时文件 + 原子重命名，不会读到半截文件）。

**Q：数据存在哪里？**
全部在服务器 `data/` 目录：`sessions.json` 是各场次的样品与评分记录，`config.json` 是评分标准、知情同意书、管理密码和当前场次。**拷贝 `data/` 就等于备份了全部数据。**

**Q：为什么某个指标没有标出显著性字母（或显示"差异不显著"）？**
说明该指标下各样品均值差异未达到所选显著性水平（默认 α=0.05）。可尝试把 α 调到 0.10 再观察；若仍不显著，通常是该指标评分区分度不够，属于真实结论，不建议人为调整数据。

**Q：分析里说"样本不足"，图表是空的？**
方差分析至少需要**每个样品 ≥ 2 条已提交记录**才能计算组内变异。请等评价员提交后再看；已提交数量会显示在分析页顶部。

**Q：导出的 PNG 背景是透明的？**
PNG 背景为白色，可直接用于报告。若需要透明背景，请导出 SVG 后在 AI / Figma / PPT 里另存。

**Q：想先看看数据分析长什么样，但还没有真实数据？**
服务启动后，另开一个终端执行 `node tools/seed-demo.js`，会造一批仿真数据（2 个场次、26 名评价员），打开管理端「数据分析 · ANOVA」即可预览全部图表与统计结果。看完执行 `node tools/seed-demo.js --clear` 一键清空，恢复干净状态。**正式评价前请务必清空演示数据。**

**Q：忘了管理密码？**
删除 `data/config.json` 中的 `adminSalt` / `adminHash` 两个字段并重启服务，密码会重置为 `admin123`（其余数据不受影响）。或者启动时用 `ADMIN_PASSWORD=xxx` 覆盖。

**Q：想让评价员只能在内网访问？**
启动时设 `HOST=127.0.0.1`，只允许通过 Nginx 反代访问；或用服务器防火墙限制 8200 端口来源 IP。

## 九、评价依据

评分标准严格对照以下文件实现，可在管理端「系统设置 → 评分标准编辑」中调整：

- GB/T 20980—2021《饼干质量通则》酥性饼干感官要求
- GB 7100—2015《食品安全国家标准 饼干》
- 《啤酒麦糟酥性饼干感官评价方案》表 1、表 2

| 评价项目 | 分值 | 一档 | 二档 | 三档 |
|---|---|---|---|---|
| 形态 | 20 | 16～20 | 11～15 | 1～10 |
| 色泽 | 20 | 16～20 | 11～15 | 1～10 |
| 滋味与口感 | 30 | 25～30 | 13～24 | 1～12 |
| 组织 | 15 | 12～15 | 6～11 | 1～5 |
| 整体接受度 | 15 | 12～15 | 6～11 | 1～5 |
| **合计** | **100** | | | |
